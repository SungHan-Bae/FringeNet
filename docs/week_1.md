## 08-12 (수) — Task 6: Stage A 파라미터화 확정 + 게이트 개정

**설계의 분기점은 파라미터화였다.** 채널 파장 / SiN n / Si n·k 를 전부 독립 자유도로 두면
(채널별 자유 곡선 ~900개) 재구성 RMSE는 노이즈 바닥까지 내려가지만, 뒤 둘이 물리적으로
λ의 함수라는 제약이 사라진다 — 손잡이가 모델 오차를 흡수해 전체 게이트는 통과해도 나온
값은 물성이 아니다(k_Si가 λ에 대해 톱니로 진동하는 식). 그래서 **자유도를 1~7개로 묶고**,
게이트도 잔차만 보지 않도록 개정했다.

- **σ 확정: 0.008658** (채널축 m차 차분이 m=5~8에서 6자리 고정). 평평해진다는 것 자체가
  잔차가 채널축에서 백색이라는 근거다. 두께축으로는 같은 추정이 불가능(과소표집).
- **🔴 노이즈가 유계임을 확정: |ε| ≤ 0.0152.** 1.83억 관측 중 R < −0.0152가 0건이고
  σ√3 = 0.014996이다(가우시안이면 5σ = −0.043까지 나와야 한다). → **새 게이트 (b)**:
  잔차가 이를 넘는 관측 하나하나가 **통계 없이** 모델 오류의 증거다. 이 잣대로 재보니
  채널별 자유 곡선 판본은 8.5% 위반 — 잔차 RMSE만 보는 게이트로는 보이지 않던 오차다.
- **게이트를 (a)~(f) 6종으로 개정.** 잔차만 보는 게이트는 계통오차를 파라미터로 흡수하는
  모델을 항상 유리하게 만들므로, **홀드아웃 예측력(e)** 과 **파라미터 물리성(f)** 을
  함께 본다 — (e)는 채널별 자유 모델이 원리적으로 통과할 수 없는 검정이다.
- 착수 전 확인: SiN을 문헌값에 동결하면 안 된다(게이지-불변 관측량이 −2.15% 편차) ·
  Cauchy 절단 근사는 잔차의 원인이 아니다 · 채널별 λ를 그대로 고정하면 안 된다.
- 두께축 주파수 식별을 `src/physics/freq_id.py`로 분리해 **run 하나가 자기완결적**이
  되게 했다 (외부 산출물을 참조하면 재현이 깨진다).

## 08-13 (목) — Stage A 종결 + 전수 리뷰

**Task 6 종결: 자유 파라미터 7개 + Si 표 Schinke 2015.** RMSE 0.009573 (1.106σ)로
게이트 (a) 통과, 두께 역해 MAE 0.340 nm, 채널 홀드아웃·λ 절대 스케일 검정 통과,
물성 전부 문헌 정합. **게이트 (b)는 미통과(9.99%)** — 채택 근거와 수용 리스크는
README §3.2에 명시. 취합: [reports/stage_a.md](../reports/stage_a.md).

- **Si 실측표 + 에너지축 스플라인이 단일 최대 기여**: 같은 자유도 1개로 역해 MAE
  1.104 → 0.663 nm. 거친 19점 표는 E1 봉우리를 4.3% 깎는다 — 거친 표 위에서 "문헌보다
  뾰족한 임계점을 복원했다"고 읽으면 안 된다(선형 보간으로 깎인 봉우리를 피팅이 되메운
  것이다).
- **🔴 Si 표 선택 근거를 기하학에서 측정으로 교체.** "Aspnes만 0.1 eV 균등 격자라 E1에
  격자점이 놓인다"는 논거가 반증됐다 — 에너지축 스플라인이 10 nm λ 격자에서도 봉우리를
  복원해 세 표의 E1 위치가 3.5 meV 이내로 일치한다. `si_source`만 바꿔 셋을 전부 적합하니
  네 지표가 같은 순서로 정렬 → **Schinke 채택**(위반율 −17%, 역해 MAE −12%).
- **🔴 test.csv의 두께는 10 nm 격자 위에 없다 — 연속이다.** 라벨이 없어 관측 불가라
  train과 같다고 암묵 가정해 왔는데, 유계 노이즈 반증과 디코더 역해가 독립적으로 일치한다.
  → 격자 스냅은 **train/holdout에서만 누설**이고 test(제출)에서는 MAE를 약 +1.2 nm
  악화시킨다. 그리고 "합성해야 한다"던 격자 밖 일반화 평가셋이 **이미 test로 존재한다**.
- **λ 절대 스케일 검정 통과** (s = 1.00689): 위상 정보만으로는 (n, λ) 공통 스케일이
  축퇴라 원리적으로 검증 불가한데, Si를 에너지축에 동결해 임계점을 절대 앵커로 쓰면
  Fresnel **진폭**이 축퇴를 깬다.
- **게이트 (e)가 판별력을 갖게 됐다**: 균등 간격 20채널은 한계 효과 +0.3%로 사실상
  보간이었다. 단파장 끝 **연속 블록**에서 +19.7%이고 그래도 예측이 성립한다.
- **🔴 게이트 (b) 후속 우선순위를 측정으로 재배열.** 채택 모델의 최악 채널은 E1이 아니라
  대역 단파장 끝(ch222–225)이고, **그 구간에는 문헌표 불일치가 거의 없다**(0.38σ, 기준보다
  작다) — 표로 설명되지 않는 모델 부족이다. 반면 E1 구역은 위반율과 표 불일치가 함께
  크다. → ① SiN 단파장 분산 + 층 k=0 ② 임계점 파라메트릭 모형 ③ 계면층 순.
- 겪은 함정: 백그라운드 run이 도는 중에 `src/`를 편집해 `PARAM_NAMES`는 새 것,
  `inits`는 옛 것인 순간에 걸려 크래시. **run 중에는 `src/`를 건드리지 않는다.**

### 적합 수준을 맞춘 재분석 — 손해의 대부분은 최적화 지연, 남은 몫도 손해 쪽

최종 에폭끼리의 비교는 **적합 수준이 다른 지점을 맞댄다**. 축을 에폭에서 `train_l1`(물리 항을
뺀 지도 항 MAE)로 바꿔 같은 적합에서 대조했다 — `scripts/analyze_stage_b_curves.py`, 취합
[reports/stage_b_curves.md](../reports/stage_b_curves.md). 학습 없이 커밋된 로그만으로 돈다.

- **손해의 대부분이 최적화 지연이다.** β=100은 30에폭을 다 쓰고도 대조군의 21에폭 수준에
  머문다(학습의 28%를 물리 항이 삼켰다. β=300은 51%). 같은 적합에서의 Δ holdout MAE는 어느
  β에서도 **0.05 nm 미만**이고, 원 비교의 나머지 열화(최대 1.21 nm)는 전부 지연 몫이다.
- **격차가 β와 함께 줄어든 것은 정규화의 증거가 아니었다.** 같은 적합 수준에서 보면 대조군의
  격차가 오히려 더 작다(β=100 지점 0.088 vs 0.042). 덜 적합된 모델은 격차가 자명하게 작다 →
  **적합 수준을 맞추지 않은 격차 비교는 읽지 않는다.**
- **남은 몫은 중립이 아니라 손해 쪽이다.** 이득이 있으려면 Δval이 음수여야 하는데(β>0 곡선이
  대조군 아래) 적합 구간 절단 3종 × run 3개 = **8개 추정 전부 양수**로, β>0가 더 좋게 나오는
  조합이 하나도 없다. 다만 부트스트랩 95% CI가 절단에 따라 0을 포함하므로 **부호는 일관되고
  크기는 분해되지 않는다** — 에폭별 val 지터 0.02~0.13 nm가 0.05 nm 효과를 가린다.
  → **절단을 하나 골라 별을 붙이지 않는다** (셋을 다 싣는다).
- **손해 방향은 착수 전에 선언한 두 근거와 맞는다** — 사전등록 1(물리 항은 `R_obs = R(d) + ε`의
  노이즈 낀 대리라 정보를 더하지 않고 gradient에 ε를 더한다) · README §3.2의 수용 리스크
  (게이트 (b) 미통과 디코더가 0.34 nm 계통 편향을 가진 기준으로 예측을 당긴다).
  **이 재분석이 그 리스크의 측정값이다.**
- 물리 항은 **같은 적합에서도 자기 목적함수를 개선한다**(val_phys −0.006 ~ −0.021). 목적이
  두께 정확도와 정렬돼 있지 않다는 진단이 이 축에서도 유지된다.
- 그림 라벨은 영문으로 둔다 — 저장소의 기존 그림 규약이고 한글 폰트는 환경 의존이라

### 라운드 3 준비 — 수렴 후 물리 fine-tune (`train.init_from`)

라운드 1·2가 **랜덤 초기화에서** 물리 항을 켠 것만 시험했다는 것이 남은 구멍이다. 물리 손실

체크포인트에서 출발해 40에폭 fine-tune하며 같은 β 4개를 대조한다
(`configs/stage_b/ft-heldout-beta*.yaml`, `notebooks/stage_b/round3_finetune-from-converged.ipynb`).

- **이 split을 고른 이유**: 라운드 2 대조군의 후반 val은 **흔들리는 정체 구간**이다 (24~30에폭

  들어간다** — 그때 "물리 항이 정규화로 작동하나"가 검정 가능해진다 (무작위 split은 라벨이

  **마지막 에폭이 best이고 아직 하강 중에 LR이 0으로 소진돼** 끝났다 (라운드 1·2와 같은 패턴).
  그 상태로는 "수렴 지점에서 물리 항이 작동하나"를 판정할 수 없다. → **epochs 40**
  (41,520스텝 = 원 학습 대비 4배, 4런 합계 55.1초/에폭 실측으로 약 37분). lr 1e-4 코사인의 적분
  LR이 라운드 2의 약 1/7.5라 40에폭을 돌려도 재학습이 아니라 국소 정련에 머문다(warm start 전제).
- **🔴 "β=0 대조군은 이미 수렴해서 거의 안 변한다"는 근거가 없었다.** 로그를 보면 라운드 1
  대조군은 26→29에폭에서 val이 계속 갱신 중이었고(에폭당 약 −0.019 nm) 멈춘 이유는 **LR이 0으로
  소진된 것**이다(에폭 29 lr 2.9e-06 → 30에서 0). → 새 LR을 주면 대조군도 움직인다. **대조군
  없이는 어떤 개선도 물리항 공로로 읽을 수 없다.** 그리고 warm start는 교란을 없애는 게 아니라
  **짧은 구간으로 줄일 뿐**이므로 fine-tune 결과도 `train_l1` 축으로 다시 읽어야 한다.
- 사전등록: 작은 β에서 소폭 이득, β=300은 여전히 열화(U자). **반증 조건** — 여기서도 단조
  열화면 "물리 손실은 초기화와 무관하게 통하지 않는다"로 닫고, 최적화 지연 설명이 부분적이었다는
  사실도 함께 기록한다. 상세는 노트북 헤더.
- **`train.init_from` 계약**: 분할이 다르면 누수이므로 출처 `metrics.json`의 `data` 블록을 대조해
  **학습 전에** 막는다. 미러에서 model.pt만 받아 대조가 불가능하면 그 사실을 로그에 남긴다.
  테스트 6종(적재·분할 불일치·구조 불일치·부재 안내·대조 불가 경고·resume 지문 분리).
- **🔴 완료 run 스킵이 설정을 대조하지 않았다** — `metrics.json`이 있으면 그냥 건너뛰었다.
  예산만 늘려 재실행하면 **옛 예산의 수치를 조용히 돌려주는** 자리다(8에폭 산출물이 남은 채
  40에폭으로 바꾸면 그렇게 된다). `metrics.json`이 설정 스냅샷을 겸하므로 대조가 가능하다 →
  다르면 학습 전에 에러를 내고 지울 경로를 알려준다(`stale_config_keys`). 스냅샷이 없는 옛 run은
  대조 불가라 허용한다(막으면 재실행이 안 된다). 테스트 4종.
- 로컬 CPU 스모크 통과 — warm start 적재(출처 val MAE 로그) · 분할 일치 대조 · 유효 beta 100 도달.
- 노트북에 셀 둘을 새로 넣었다. ① **warm start 체크포인트 회수** — 미러에서 model.pt만 가져온다
  (텍스트 2종은 git이 정본이라 미러 사본으로 덮으면 안 된다). ② **설정이 다른 같은 이름 run 정리**
  — 위 가드가 에러를 내는 자리를 Run-All이 스스로 통과하게 한다. 설정이 **같은** 완료 run은
  건드리지 않으므로 세션 유실 후 스킵·재개 계약은 그대로다.
- 노트북 산문에서 **셀 번호 참조를 걷어냈다** — 셀 하나를 끼우면 전부 밀린다. 내용으로 가리킨다
  ("push 셀", "요약 셀").

### 라운드 3 결과 — 초기화 구멍도 닫혔다. 물리 손실 항은 종결

4런 완주(40에폭), 출발선 4.0612 nm. 정본은 `runs/stage_b/ft-heldout-*/metrics.json`과
[reports/stage_b_curves_ft-heldout.md](../reports/stage_b_curves_ft-heldout.md).

- **40에폭이 맞았다.** best 에폭이 36/36/38/32로 마지막이 아니다 — 8에폭 때와 달리 실제로
  수렴했다. 대조군의 37~40에폭 val이 3.835/3.833/3.848/3.835로 평평하다.
- **사전등록 1 부합**: 대조군이 4.0612 → **3.8313**(−0.2299)으로 크게 움직였다. 예산만 더
  줘도 이만큼 좋아지므로, 대조군 없이는 어떤 개선도 물리항 공로로 읽을 수 없었다.
- **🔴 사전등록 2 어긋남 — 또 단조 열화다** (3.8313 / 3.8498 / 3.9501 / 4.1116). 수렴 지점에서
  출발해도 β>0가 대조군을 못 넘는다. **반증 조건 성립 → 물리 손실 항은 초기화와 무관하게 이
  문제에서 통하지 않는다.** 세 축(무작위 split · held-out 두께 · warm start)에서 모두 같은
  결론이므로 Task 7의 물리 손실 질문은 종결이다.
- **다만 적합 수준을 맞추면 차이가 사라진다** — 세 β의 CI가 모두 0을 포함한다(|중앙값| ≤
  0.005 nm). 라운드 2에는 남아 있던 작은 해로운 잔차가 warm start로 없어졌다. 즉 **손해는
  전부 최적화 지연**이고, 수렴 지점 출발이 그 잔차만 제거했다.
- **🔴 β=300은 warm start 지점보다 `train_l1`을 밀어올린다** (2.6614 → 2.6959, 6에폭 상승 후
  하강). 물리 항의 gradient가 느린 게 아니라 **역문제를 푸는 방향으로 나쁘다**는 직접 증거다.

### 라운드 3에서 드러난 결함 넷 (전부 수정)

- **🔴 미러 복원이 `resume.pt` 없이도 `train.log`·`model.pt`를 끌어왔다.** 이어 달릴 상태가
  없으면 그 파일은 **중단된 다른 run의 기록**이다. → resume.pt가 있을 때만 복원하고, 없으면
  그 사실을 로그에 남기고 처음부터 학습한다. 테스트 2종(복원 안 함 / 정상 재개는 그대로).
- **분석의 단조성 가드가 너무 엄격했다.** 수렴 지점에서 에폭 평균 `train_l1`이 1e-4 규모로
  되튀는데(2.1216 → 2.1218) 그것까지 막아 수렴한 run을 못 읽었다. → 전체 폭의 2% 이내 되튐은
  허용하고 보간을 train 축 **정렬** 기반으로 바꿨다.
- **warm start run은 train 축이 단조가 아니다** (β=300이 되돌아온다). 곡선이 되돌아오면 val은
  train_l1의 함수가 아니므로 **하강 구간만** 쓰고 무엇을 잘랐는지 출력한다.
  누적 로그도 `epoch N/total`의 total로 걸러낸다.
- **🔴 그림 제목이 라운드 1 결론을 하드코딩했다** — "at matched fit it is never better"가 라운드
  3에서 거짓이 된다. → 제목·소제목을 데이터에서 만든다. 패널 (a)도 축을 각각 데이터에서 잡고
  범위가 좁으면 선형으로 바꾼다(로그 눈금이 두어 개만 걸려 짜부라졌다).
- **🔴 §1의 단일 에폭 Δ에는 선택 편향이 있다** — best 에폭은 val 최소가 되도록 **골라진**
  지점인데 대조군 보간값은 그렇지 않다. 라운드 3에서 세 β의 Δ가 −0.0154/−0.0155/−0.0151로
  수상하게 균일했던 원인이다(실측 편향 −0.011 nm). 리포트가 그 크기를 산출해 함께 싣고,
  **판정은 §2의 에폭별 분포로** 한다.

### 역산 refinement — 사전등록 2 부합. 물리는 추론에서 값어치가 있다

손실 항이 세 축에서 기각된 뒤 남은 질문에 답했다. 정본은
[reports/inversion_refine.md](../reports/inversion_refine.md)와 그림 `fig_inversion_refine.png`.

- **holdout 81,000행에서 2.3455 → 0.6110 nm (−74%)**, 98%의 행이 개선된다. 라벨도 격자도
  쓰지 않으므로 test에 그대로 적용된다. 상한(참값 출발)이 0.3336이고 이는 게이트 (d)의
  0.3402와 다른 표본에서 일치한다.
- **🔴 대조군이 서사를 확정했다** — 격자 중앙(155 nm)에서 출발한 같은 LM은 **77.68 nm**로
  실패한다(98.3%가 분지 실패). 즉 **CNN이 하는 일은 정밀도가 아니라 올바른 fringe 분지
  찾기**이고, 물리가 하는 일은 그 분지 안의 정밀화다. 둘은 다른 일을 한다 — 이것이 β 손실이
  실패한 이유이기도 하다(손실 항은 CNN에게 이미 할 줄 아는 일을 시켰다).
- 십분위별로 보면 1~9분위가 전부 0.25~0.47 nm로 **평평해진다**. 남은 오차는 사실상 10분위
  (3.21 nm)와 0.67%의 분지 실패 행에 몰려 있다.
- **이동 상한 τ 규칙은 이득이 없다** — τ를 걸수록 단조로 나빠지고 τ=∞(원안)가 최선이다.
  τ를 holdout으로 고르는 것은 평가셋 선택이므로 곡선을 통째로 싣고 판정은 원안으로 했다.
- **비교 기준선**: 같은 holdout에서 213M skip-MLP가 0.3955 nm다. 0.66M CNN + 물리 보정이
  그 격차의 89%를 지우지만 **넘지는 못한다** (0.611 vs 0.396).

### 그 대신 추론 지연은 손해다 — 재서 같이 싣는다

"작은 모델 + 물리"가 지연에서도 싸냐는 질문이 나와 측정했다
([reports/inversion_bench.md](../reports/inversion_bench.md), `scripts/bench_invert.py`).

파라미터 수와 연산량이 갈라지는 자리다: 디코더는 자유 파라미터가 7개인데 호출당 226채널 ×
4층의 복소 cos/sin을 돌고, LM이 그걸 **행당 270회** 부른다.

- **`cnn+LM`은 213M skip-MLP forward보다 한 자릿수 느리다** — L4에서 17.26배. 그리고 **GPU가
  격차를 좁히기는커녕 벌렸다** (Colab CPU 13.16 → L4 17.26). skip-MLP는 GEMM 한 방이라 GPU를
  온전히 먹고 LM은 덜 먹기 때문이다.
- **🔴 단일 배수를 인용하면 안 된다** — 같은 코드가 로컬 WSL2에서는 6.4배, Colab CPU에서는
  13.2배다. skip-MLP GEMM이 Colab CPU에서 3.7배 빨라지는 동안 LM은 1.8배만 빨라졌다
  (비정형 연산 + 대역폭 바운드라 BLAS·하드웨어 최적화의 혜택을 덜 받는다). 배수는 항상
  기계와 함께 적는다.
- **GPU 이득의 절반 이상을 float64가 먹는다** — LM complex128은 10.3배 빨라지는데 complex64는
  24.5배다(소비자 GPU FP64 1/32, 사전 예상 부합). 절대 시간으로는 c128 0.814 → c64 0.238 ms/행.
  MAE는 0.6630 vs 0.6653으로 사실상 같다 → **배포 경로는 complex64**, 판정은 complex128.
- **🔴 반복수를 줄이는 것은 공짜가 아니었다** — 10회는 30회보다 MAE가 0.02~0.03 nm 나쁘다
  (로컬 +0.024 · Colab CPU +0.020 · L4 +0.031, 같은 dtype끼리 비교). 3배 싸지는 대신 치르는
  값이고, 0.611 nm 기준 약 5%다. 조기 종료 여지는 있지만 "같다"고 쓸 수 없다.
- CPU↔GPU는 같은 표본·같은 알고리즘인데 MAE가 1.8% 다르다 (0.6752 vs 0.6630) — 축약 순서와
  배치 solver 구현 차이다. `CPU↔GPU는 bit 재현이 아니라 MAE 수준에서 비교한다` 규약이 걸리는 자리.
- **실용적 함의**: 전체 holdout 재생성이 로컬 CPU에서 55분 걸렸는데 L4의 0.814 ms/행을 그대로
  곱하면(× 81,000행 × 3팔) 3.3분이다. 리포트 재생성을 GPU로 옮기면 반복 실험 비용이 사라진다.
- 미착수 레버는 해석적 야코비안(디코더가 미분가능한데 정작 역해는 중앙차분을 쓴다) ·
  수렴 행 조기 종료. **안 한 최적화를 근거로 쓰지 않는다** — 리포트는 현재 실측을 싣는다.

### 표본 수 민감도 — 디코더를 더 많은 데이터로 적합하면 좋아지는가 (아니다)

캘리브레이션이 train 729,000행 중 **8,000행**만 쓴다는 지적이 나왔다. config 주석은 "자유도
7에 관측 180만 개라 표본이 병목이 아니다"라고 적혀 있었지만 그건 **논증이지 측정이 아니었다.**
`fit_rows`만 다른 run 둘을 추가해 재고 게이트 리포트에 «표본 수 민감도» 절로 넣었다.

- **2k / 8k / 50k(25배 범위)에서 RMSE·계통오차가 6자리 동일**하고 역해 MAE는 0.3404 / 0.3402 /
  0.3402다. 물성값도 0.7% 안쪽에서 같다. 50,000은 분할 계약의 상한이고(그 위는 판정 표본과
  겹친다), 8k → 50k가 통계오차를 2.5배 줄이는 폭이므로 train 전체로 늘려도 결과는 같다.
- **왜 그런지가 오차 예산에 나온다.** 계통오차 0.004085를 층별 민감도(ΔR/nm)로 나누면 두께
  0.31~0.46 nm이고, 노이즈 몫은 σ/√226 기준 0.04~0.06 nm다. 실측 상한 0.3336 nm은 **계통 몫과
  같은 자리**이고 층 순서(layer_2 최악·layer_3 최선)까지 맞는다. 표본을 늘리면 줄어드는 것은
  이보다 더 작은 파라미터 추정 분산뿐이다.
- **파급**: 디코더를 개선하려면 데이터가 아니라 **모델 형태**를 손봐야 한다. 그리고 그 값이
  올랐다 — 0.3336은 역산 refinement 전체의 천장이고, refinement가 이제 Task 7의 주 결과다.
  게이트 (b) 후속을 미룬 이유("성공 기준 #2가 0%인 상태에서 forward를 더 파는 것은 순손실")는
  **더 이상 성립하지 않는다.**
